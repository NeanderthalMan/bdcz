# v124 — the advocates view's iTerm tab buttons (bc-4olsx)

Every card on the advocates view grows an **iTerm tabs** row — Consolidate, Close all
(two taps, armed in between) and Reopen — wired to `POST /api/tabs/*` (lib/tabpark.js).
Two files in `SHELL` change together and **draw and style halves of the same control**.

| half | what is new |
|---|---|
| `public/monitor.js` | `tabsStrip`, `tabsSentence`, `tabsAction`; `state.armedTabs` / `tabsBusy` / `tabsSaid`; the `[data-tabs]` click branch |
| `public/style.css` | `.tab-ctl`, `.tab-ctl-label`, `.tab-ctl-said`, `.tab-skipped`, `.adv-btn.armed` |

**A mixed pair is a control with no layout.** v123's `style.css` against v124's
`monitor.js` draws the row as three pills run straight into the label with no wrap, the
armed Close as an unchanged pill (so the confirm tap reads as a press that did nothing),
and the skipped list as a bulleted run with default margins. The page still works, so
nothing on screen says the halves disagree. The other direction, v124's `style.css`
against v123's `monitor.js`, styles classes nothing draws and is harmless. Nothing v123
changed in `style.css` (the bar, the rail, the docked drawer, Find) touches these
classes, so the pairs are the same as they were when this was written against v117.

**`SHELL` is unchanged.** No file is added or renamed.
