# v115 — one proposal card, on all three screens (bc-yjekg.5)

`public/proposal.js` is new and is **added to `SHELL`**. It holds what `public/app.js`
used to write out on its own: the rows of a proposal, the ✓/✎/✕ per bead, the duplicate
warning, the fold on a long row, the adjust editor and the two bulk controls that each
name the number the next tap will file. `public/monitor.js` (the Advocates pane) and
`public/mirror.js` (the Mirror) mount it instead of drawing their own. This is the
change #95 (bc-iaju1.7) specified, redone on current main rather than rebased.

| half | what is new |
|---|---|
| `public/proposal.js` | **new file, in `SHELL`** — the card, the pick/edit state, and `bind()` for a mount |
| `public/app.js` | keeps `proposalHtml` / `propBulkHtml` / `propBulkLabel` / `paintPicks` as thin mounts; its four proposal click branches become one `props.onClick(ev)` |
| `public/monitor.js` | loses its own `picksFor` and `proposalHtml` rows; gains the fold, the editor and `edits` on its submit |
| `public/mirror.js` | loses the "per-bead buttons live on the Advocates tab" sentence and gains the buttons |
| `public/index.html`, `public/monitor.html` | load `/proposal.js` above every script that mounts it — an eager tag above `app.js` on `index.html`, which is ahead of `monitor.js` and `mirror.js` too since `public/panelazy.js` injects those after every eager tag has run |
| `public/style.css` | the `.mon-bead*` / `.mir-prop*` rules the two deleted renderers wore are gone; the pair drawn *under* the rows gets its own separation |

**The mix worth stating, because this bump adds a file.** A v114 page holding v114's
`app.js` and `monitor.js` never asks for `/proposal.js` and is consistent with itself — it
draws the old three cards. The bad mix is the other direction: a page that took the new
`app.js` without the new shell would find `window.beadcause.proposal` undefined and throw
where the inbox mounts the card. That is why the file is precached beside `app.js` rather
than left to network-first — the two are one unit now.

**Nothing on the server changed.** `/api/respond` already took `create` and `edits`; what
is new is that the Advocates pane and the Mirror send them too.
