# v121 — All settings, every config.json key on a page (bc-qzng7.5)

The Settings screen's **All settings** page stops being a sentence about a bead that was
not built yet and becomes the page: every key docs/config.md documents, grouped, searchable,
each with its value, default, source, description and a typed editor, a log of the changes
made from it with Revert, and a Restart button for the keys that wait for one. It reads
`GET /api/config` and writes `POST /api/config`, both new in this release. Two files in
`SHELL` change together.

| half | what is new |
|---|---|
| `public/config.js` | `allHtml` draws the catalogue; `loadAll`, `allClick`, `allInput`, `allFilter`, `allWrite`; the `cfg-*` editors and their `data-cfg-*` presses |
| `public/style.css` | `.cfg-search`, `.cfg-group`, `.cfg-key`, `.cfg-badge`, `.cfg-body`, `.cfg-facts`, `.cfg-pw`, `.cfg-in`, `.cfg-json`, `.cfg-log*`, `.cfg-restart` |

**A mixed pair is ugly rather than broken, and the version is for the ugly direction.**
v121's `config.js` against an older `style.css` draws two hundred keys as unstyled
`<details>` with bare selects and textareas — usable, and a page nobody would call
finished. The other direction, an older `config.js` against v121's stylesheet, is the old
"not built yet" sentence with a few unused rules beside it, which is harmless.

**And the daemon side is not in the shell.** `/api/config` arrives with the daemon, not the
cache. A phone holding v121's `config.js` against a daemon that predates the route gets a
404 on the page and draws the error in a sentence; nothing else on the Settings screen
reads it.

**`SHELL` is unchanged.** No file is added or renamed: the page lives in `public/config.js`
rather than a file of its own, because a new pane script is a line in `SHELL`, a line in
public/panelazy.js's list and four suites that pin that list, all to save one file a few
hundred lines.

## The number, and the gap below it

Claimed as **v121** while `main` is at v118 and two sibling phases of the same epic
(bc-qzng7) hold **v119** and **v120** on branches that have not landed. So on this branch
alone `node test/swcache.mjs` reports "no note for v119, v120" — that is those two notes
not being here yet, not a renumber that skipped, and it clears as they merge. Taking a
lower number instead would collide with a sibling on the same path. If this lands first,
or one of them moves, renumber to the next free version above whatever `main` holds and
restate the pairs.
